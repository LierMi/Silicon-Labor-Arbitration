# 桌面档案流 UI 交互设计方案

> 状态：已落地到 `/demo` 第一版
> 范围：前端桌面 Web 演示、mock 案件、纵向分镜滚动
> 原则：做卷宗，不做判决机；做证据流，不做 Web3 霓虹页。

## 1. 设计总纲

本版采用“桌面档案流 + 纵向分镜滚动 + 强视觉留白 + 流程推进”。
用户不是进入一个 Dashboard，而是在一张办案桌上依次打开卷宗、核对证据、查看责任链、运行规则、看到 C4 空章悬停，再进入人工复核。

本版明确是 **桌面 Web 版式**，不是移动端版式。画布下限为 1280px，1440px 为主要验收宽度；窄屏只允许横向查看桌面画布，不切换成手机导航或单列移动布局。

核心记忆点：

- 证据都在，但责任落点缺席。
- C1-C3 可以落章，C4 必须停住。
- AI 只解释，且每句话必须回到证据编号。
- 钱由客观规则和事前权重拆分，主观部分冻结给人。

## 2. 后端字段到 UI 的映射

| 后端字段 | UI 责任 | 交互要求 |
|---|---|---|
| `Case.status` | 案件状态轨 | 必须渲染全部 8 个状态，并突出当前状态 |
| `CASE_TRANSITIONS` | 下一步提示 | 显示当前状态允许进入的后续状态 |
| `evidence[]` | 桌面碎片、证据抽屉、引用角标 | 点击 `[E1]` / `[E2]` / `[E3]` 打开证据抽屉 |
| `evidence.source` | 证据来源 | Moss / Direct / Offchain 必须有视觉区别 |
| `requirements[]` | C1-C4 条款纸 | 每条显示编号、权重、客观/主观属性 |
| `ruleResults[]` | 章位状态 | `satisfied` 落章，`violated` 驳回，`undecidable` 悬停空章 |
| `settlementProposal` | 资金账本 | 字符串金额直接展示，不转 number |
| `responsibilityChain[]` | 责任断层和时间线 | hover / click 一跳责任链时高亮对应层片 |
| `aiArguments[]` | 三路证词纸 | 文本中的证据编号必须可点击 |
| `mossPreSign` | Moss 签前证据 | 展示解释、ABI hash、canonical payload 和钱包一致性预留 |

## 3. 分镜版式

### Scene 01：责任碎片

首屏展示 E1、E2、E3、Agent log、wallet signature、tool params 等纸片悬浮在桌面上。
鼠标移动时碎片轻微漂移，但中心空洞不动。

目标：第一眼传达“所有证据都在，责任中心缺席”。

### Scene 02：案件开卷

展示主卷宗纸：

- 案件编号、标题、当前状态、mock 标记。
- E1 原始需求钉在左侧。
- E3 Moss 签前证据钉在右侧。
- wallet consistency 区域作为后续真实钱包接入的预留。

目标：让评委看到这不是静态海报，是真实案件结构。

### Scene 03：责任断层

使用 exploded axonometric 方式表达责任链：

- Human Intent
- Main Agent
- Worker Agent
- Tool
- Wallet
- Delivery

每一层对应 `responsibilityChain[]` 一跳。
hover 时间线或层片时双向高亮。

目标：用空间错位表现“责任在转译中变薄”。

### Scene 04：规则盖章

中央是 C1-C4 条款纸，右侧是资金账本。

- C1-C3 按顺序落“满足”章。
- C4 章落到一半停住，只留下阴影和空章位。
- 资金账本显示 `0.15 MON / 0 / 0.05 MON`。

目标：让 C4 空章悬停成为全站高潮。

### Scene 05：AI 三路意见

三张证词纸并排：

- 检方意见
- 辩方意见
- 审计意见

所有 `[E1] [E2] [E3]` 都是按钮，点击打开证据抽屉。

目标：明确 AI 是解释层，不是资金层。

### Scene 06：归档报告

展示案件归档摘要：

- 证据数量。
- 责任链 hops。
- 冻结金额。
- 人工复核入口。

目标：收束到“终审仍在人手里”，不输出终局裁决。

## 4. 视觉规范

- 背景：浅米色档案纸 + 细网格。
- 主色：机构绿 `#123e32`。
- 警示/印章：暗红 `#aa3d32`。
- 纸张：牛皮纸、米白纸、低对比边线。
- 文字：黑色/深棕，少量 muted 灰棕。
- 避免：蓝紫渐变、霓虹粒子、AI 头像、法院图标、金色天平、普通后台卡片堆叠。

## 5. 动效规范

- 只让服务叙事的元素动。
- 首屏碎片：跟随鼠标轻微漂移，幅度小，中心空洞保持稳定。
- 责任断层：hover 时轻微抬升和加深，不做夸张镜头。
- C1-C3：落章有随机感和印泥感。
- C4：半空悬停、低频颤动、纸面留白、没有章痕。
- `prefers-reduced-motion` 下关闭长动画。

## 6. 验收清单

- [ ] 第一眼像未签署的责任卷宗，不像 Web3 官网或普通 Dashboard。
- [ ] 1440px 桌面 Web 画布是主验收尺寸，左侧保持竖向页码轨。
- [ ] 小于 1280px 的窄屏不启用移动端重排，只横向查看桌面画布。
- [ ] 6 个场景可纵向滚动浏览。
- [ ] 左侧页码轨能跳转并显示当前场景。
- [ ] E1/E2/E3 证据纸可点击打开抽屉。
- [ ] Moss / Direct / Offchain 视觉来源区分清楚。
- [ ] 8 个案件状态全部可见，当前状态突出。
- [ ] 责任链 hover / click 能高亮层片。
- [ ] C1-C3 落章，C4 悬停空章。
- [ ] 资金账本金额与 `settlementProposal` 一致。
- [ ] AI 三路意见中的证据编号可点击。
- [ ] Mock data 标记清楚，不伪装真实链上案件。

## 7. 后续可增强项

- 使用真实纸纹、印泥、档案边角素材替换纯 CSS 质感。
- 若 CSS 章动画不够稳，再引入 GSAP 控制 C4 时间轴。
- 若责任断层需要更强空间感，再用 Spline 或 R3F 替换 Scene 03 的 CSS 3D。
- 钱包接入后，将 wallet consistency 从预留区升级为真实签名前后比对。

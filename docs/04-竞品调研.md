# 硅基劳动仲裁院 · 竞品调研与差异化

> 调研日期：2026-07-29

## 一、一句话结论

**概念高度重叠，而且最强的竞品在 19 天前刚刚发布。**

但对黑客松而言这是**好消息**：它替我们证明了问题真实存在，并且给了我们一个可以正面对立的靶子。**唯一致命的情况是上台时不知道它存在。**

## 三、Internet Court 深度拆解（最重要的竞品）

由 GenLayer 基金会牵头、**27 家公司**联合发起的开放标准。参与方包括 OKX、MetaMask（Consensys）、Matter Labs（ZKsync）、0G Labs。

| 维度 | Internet Court |
|---|---|
| 定位 | AI Agent 之间纠纷的裁决标准，自称「agentic commerce 的法律基础设施」 |
| **裁决者** | **1,001 个 AI validator 轮换组成的陪审池，明确声明不含人类法官、仲裁员或陪审团** |
| 速度 / 成本 | 30–60 分钟出**终局判决**，每案约 $0.85–1.45 |
| 授权链 | **ERC-7710 delegations** —— 记录谁授权、授权范围、花费上限、时效，为仲裁者留下可验证记录 |
| 托管 | **x402 Facilitator** —— 按裁决结果释放或罚没 |
| 争议模型 | 乐观模式：默认任务成功，除非在挑战期内被质疑 |

### 它和我们重叠在哪

- 「授权链留下可验证记录供仲裁使用」= 我们的**责任链**
- 「托管按裁决结果释放或罚没」= 我们的 **TaskEscrow + Settlement**
- 「AI 参与裁决」= 我们的**检方 / 辩方 / 审计三路 AI 意见**

### 它和我们分歧在哪（这才是重点）

> Internet Court 把人从裁决中**彻底移除**，追求终局、快速、低成本、可规模化。
> 我们保留人的终审权，追求**可解释、可追溯、可申诉**。

**这是正面的哲学对立，不是功能差异。**

## 四、我们的差异点（按路演可用性排序）

### 差异点 1：AI 判人 vs 人保留终审权 ⭐️ 最强

Internet Court 的宣传原话是判决"不由人类仲裁员、法官或陪审团作出"。

而我们的原方案写的是：

> 不能简单设计成"五个 AI 投票，票多者获胜"。模型数量更多不代表更正确，**也不能自然获得审判人类的合法性**。

**可直接用于路演的一句话：**

> 当 1001 个 AI 投票决定你该不该被扣钱——**谁给了它们审判你的合法性？**

2026 年 7 月，这是一个逆潮流的、有观点的立场。黑客松评委喜欢有观点的项目胜过喜欢功能更全的项目。

---

### 差异点 2：裁判 vs 归因 ⭐️ 最本质

- **Internet Court 解决"A 和 B 谁对谁错"** —— 双边裁决，产出是 verdict。
- **我们的题目是"责任在多跳委托链里消失了"** —— 人 → 主 Agent → 子 Agent → 工具 → 钱包，每一环都有理由，最后没有主体担责。

产出物根本不同：

```
Internet Court  →  判决书
硅基劳动仲裁院  →  责任时间线
                   （哪一步偏离了原始意图、谁看见了警告仍然点了批准）
```

回到原方案里写得最好的那句话：

> **真正的被告不是人类，也不是 AI，而是责任在委托链中的消失。**

> 📌 Week3 第四方案「不是我干的 / 责任黑洞」与此同源，其责任链设计可直接并入。

---

### 差异点 3：承认不可裁决性

Internet Court 承诺 30–60 分钟必出终局判决。我们做更诚实的事——**分流**：

- 客观规则能判的 → 自动判
- 判不了的 → 明确标记「**不可自动裁决 → 转人工**」，并说明卡在哪一条

在所有人都在吹「AI 全自动」的时候，**敢标记自己判不了**，是产品诚实度，也是记忆点。

---

### 差异点 4：面向个人的可体验性

Internet Court 是 B2B 基础设施标准（27 家公司联盟），普通人一辈子碰不到。

而本届赛道的官方要求是：

> 做一个能够**被体验、被解释、被验证**的产品

| 官方要求 | 我们怎么满足 |
|---|---|
| **被体验** | 亲自当委托人：付 0.2 MON → 收到一颗土豆 → 点「拒绝付款」 |
| **被解释** | 责任链逐步展开，AI 出检方/辩方/审计意见并**引用证据编号** |
| **被验证** | 每一步都有链上交易哈希和证据哈希可查，裁决是推导不是脚本 |

**Internet Court 在结构上就满足不了「被体验」这一条。**这是我们独占的赛道优势。

---

### 差异点 5：技术栈与信任模型

| | Internet Court / GenLayer | 硅基劳动仲裁院 |
|---|---|---|
| 运行环境 | GenLayer 自有 L1 + Python Intelligent Contracts | **Monad**，标准 EVM |
| 裁决依赖 | AI validator 共识 | 链上确定性规则 + 链下 AI（仅负责解释） |
| 动钱的部分 | 依赖 AI 共识结果 | **完全不依赖 AI** |

对 Monad 赛道这是加分项：**证明不需要一条专门的 AI 链，也能做 Agent 责任归因。**

## 五、名字即论据：为什么「劳动仲裁」这个词本身就是差异点

这是本次调研最有价值的发现之一。

**在中国法律体系里，劳动仲裁本来就不是终审。**它是一道**前置程序**——不服仲裁裁决，可以依法向人民法院提起诉讼。

也就是说：

> **「仲裁」这个词本身就自带「不是终审、可以上诉」的含义。**
> 而 Internet Court 宣称的是 **binding verdict（终局判决）**。

所以我们不需要为「保留人类终审权」这个设计做任何额外辩护——**它是「劳动仲裁」这个制度的常识，是名字自带的属性。**

**路演可用的一句话：**

> 我们叫仲裁院，不叫法院。**仲裁本来就不是终审**——不服的可以上诉。
> 而 Internet Court 用 1001 个 AI 给你一个终局判决，不给上诉。

名字不用改。它在这一刻从「和论点有矛盾」变成了「论点最好的注脚」。

## 七、Q&A 弹药库

**Q1：这不就是 Internet Court 吗？**
> 机制有重叠，立场是相反的。它把人从裁决里移除，追求终局和可规模化；我们保留人的终审权，产出的是责任归因而不是判决。而且它是 27 家公司的 B2B 标准，普通人碰不到；我们做的是任何人三分钟能亲手走完一次的东西——这正是本届「能被体验」的要求。

**Q2：为什么不直接用 Kleros？**
> Kleros 解决的是「谁对谁错」，靠随机抽取的人类陪审员投票。我们解决的是「责任在委托链的哪一跳消失了」——这是归因问题，不是投票问题。而且 Kleros 的陪审员看不到 Agent 的授权范围和中间步骤，我们的证据结构天然包含这些。

**Q3：为什么不出终局判决？是做不出来吗？**
> 是设计选择，而且有制度先例。空难调查（NTSB 模式）的产出从来不是判决，而是事故报告和责任链还原，并明确声明不为诉讼定责——因为**调查的合法性来自还原事实，不来自定罪**。我们同理。另外，仲裁在法律上本就是前置程序，不是终审。

**Q4：AI 凭什么判人？**
> AI 在我们这里**不判**。三层结构：链上证据层负责事实，确定性规则层负责能客观判定的部分（预算、截止时间、格式、是否交付、是否越权），AI 只负责交叉质询和解释，且必须引用证据编号，对不确定的事实必须标注"不确定"。人保留最终申诉权。

**Q5：为什么要用 Monad？**
> 每个 `caseId` 和 `taskId` 都是独立状态——案件 A、B、C 的证据、质押、裁决、结算互不争用同一个全局变量。大量案件可以同时提交证据、进入审查、完成结算。Monad 的意义不是让单个案件更复杂，而是让未来数千个 Agent 微任务产生的争议能够低成本并行处理。我们不使用全局递增计数器，全网统计通过事件在链下 Indexer 聚合。

**Q6：现在有真实用户吗？**
> 今天还没有大规模的 Agent 争议——但 19 天前 27 家公司（含 OKX、MetaMask）刚为这个问题成立了联盟，**这个问题的真实性已经不需要我们来证明**。我们做的是当它发生时，责任怎么被找回来。

# Awesome Design 原型 · UI 设计思路

## 聚焦板块：裁决与资金结算

这一屏不是传统意义上的“判决结果页”，而是整个产品立场最集中的界面：系统只处理可测量事实，遇到主观条件时必须诚实停下。因此 UI 的核心目标不是让用户觉得“AI 很聪明”，而是让用户在一眼之内看懂三件事：哪些条件已经被确定性规则验证、哪些资金可以据此结算、以及哪一部分必须交还给人类判断。

### 1. 信息结构：从条款到资金，而不是从结论到解释

界面左侧以 C1–C4 条款列表作为主叙事线，每一条都对应一个明确的验收条件、证据来源和判定状态。这样做的好处是把“裁决”拆回可审计的最小单元，避免界面直接抛出一个总结果。右侧资金结算只承接左侧判定：C1、C2、C3 满足，所以 0.15 MON 可支付；C4 不可裁决，所以 0.05 MON 冻结。资金不是 AI 意见的结果，而是客观条款权重的结果。

### 2. 视觉隐喻：盖章不是装饰，是状态机

印章承担的是交互语言，而不是司法装饰。C1–C3 的“满足”章代表规则层已经落地，C4 上方悬停的印章代表规则层无法继续执行。空章位比一行“待人工复核”的文字更重要，因为它把产品边界变成了视觉事件：章落不下去，意味着系统不能伪装自己已经完成判断。

### 3. 版式气质：卷宗感压住产品感

这一版采用“机构绿 + 牛皮纸卷宗”的方向，避开 Web3 常见的蓝紫渐变、发光线条和粒子背景。左侧导航像档案柜目录，中间条款区像归档表格，右侧结算区像财务清单。整体不做炫技式 Dashboard，而是保持纸张、编号、细线、章位、证据角标这些可审计元素，让界面看起来像一份已经归档但仍未署名的责任文件。

### 4. 交互重点：让 C4 的“停住”成为记忆点

动效应该集中在 C4，而不是平均分散在全屏。C1–C3 可以用轻微缩放、旋转和油墨透明度变化模拟盖章；C4 则在下落到一半时停止，并保持 2–3px 的低频颤动。纸面只留下阴影，没有印记。这个停顿需要留白和静音感，不急着弹出说明，因为“系统判不了”本身就是本项目与全自动 AI 裁判叙事的最大区别。

### 5. 右侧结算：把金额做成可追责的账本

资金模块不使用收益卡片或夸张数字，而是采用账本式三行结构：支付给 Agent、退回给委托人、冻结复核。这样能明确表达资金流向来自条款权重，而不是来自 AI 偏好。冻结金额用轻微红色纸面底色提示风险，但不做警报式处理，因为 C4 不可裁决不是错误状态，而是设计立场。

### 6. 证据与三路意见：作为下钻层，不抢主画面

证据角标 E1–E3 和 AI 三路意见放在主判定区之后，承担“为什么”的下钻解释，而不是抢占首屏叙事。检方、辩方、审计三栏并置，保留《罗生门》式的多重叙述结构：每一方都有理由，但没有任何一方能越过证据编号直接给出终局判断。

### 7. 设计取舍

- 保留：编号、条款、章位、证据角标、账本式资金流。
- 克制：按钮数量、说明文字、色彩对比、装饰性图标。
- 放大：C4 空章位、悬停印章、冻结金额、人类终审入口。
- 避开：法院图标、金色天平、AI 头像、霓虹 Web3 视觉、全自动判决口吻。

### 一句话总结

这一屏要让评委记住的不是“AI 做出了判断”，而是“系统在最关键的一刻诚实地停住了”。C1–C3 是能力，C4 是边界；而这个边界，正是硅基劳动仲裁院的产品气质。
